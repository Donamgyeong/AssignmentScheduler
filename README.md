# 과제 인건비 배분 프로토타입

Windows에서 `run.bat`을 실행합니다. Python 3.10 이상과 기본 Tkinter가 필요하며 별도 패키지 설치는 없습니다. 현재 컴퓨터의 Python으로 실행할 수 있습니다.

## 사용 순서

1. 샘플 불러오기 또는 연구원/과제 추가.
2. 월 임금과 재직기간, 과제 전체 예산과 기간, 기타 지출, 참여 가능 연구원을 입력.
3. 자동 배분 실행 후 과제별 결과, 월별 배분, 미배분 임금을 검토.
4. 현재 안 확정으로 비교 기준안을 저장. 입력을 수정하고 재계산하면 기존 기준안 대비 증감을 표시.
5. 저장하거나 결과 CSV 내보내기. CSV는 Excel에서 열 수 있으며 XLSX 직접 처리는 지원하지 않습니다.

CSV 양식 저장은 현재 입력 또는 예시를 내보냅니다. 연구원을 먼저 가져온 뒤 과제를 가져오세요. 가져오기는 해당 목록 전체를 교체합니다. 참여 연구원은 이름을 쉼표로 구분하며 빈 목록에는 인건비가 배분되지 않습니다.

기존안 가져오기는 월별 기존 예산을 비교 기준으로 읽습니다. CSV 필수 열은 `employee,month,project,category,amount`이며 구분은 `kind`(현물) 또는 `cash`(현금)입니다. 내보낸 allocations.csv도 다시 가져올 수 있습니다. 기존안은 계산 가능한 잔액을 차감하거나 집행액을 고정하지 않습니다.

## 계산 규칙과 현재 범위

- 금액은 정수 원 단위. 입력기간은 월 단위이며 시작월과 종료월 모두 포함합니다.
- 월 임금 전체가 배분 가능한 인건비라는 가정입니다. 부분 재직월의 일할 계산, 임금 변경 이력, 참여율 한도는 미지원입니다.
- 각 연구원의 임금은 지정된 참여 과제와 수행기간 안에서만 배분됩니다. 동일 임금 중복 사용을 금지합니다.
- 최대 유량 알고리즘으로 전체 현물 부족 합계를 최소화합니다. 현물 배분 후 과제별 부족액을 현금 반납액으로 확보하고 남은 예산에 현금 인건비를 배분합니다.
- 입력 과제 순서에 따라 동률 해가 달라질 수 있습니다. 기존 기준안은 비교에만 사용하며 변경량 최소화는 미지원입니다.
- 현금 예산보다 기타 지출 및 예상 반납액이 크면 음수 잔액을 표시하고 확정을 차단합니다.
- 현물 인정액은 계획 인건비에서 계산한 예상치이며 실제 인정/집행 관리가 아닙니다.
- 이미 집행한 월의 고정, 수동 배분 고정, 비인건비 현물, 과제별 인정 규칙은 미지원입니다. 실제 운영 전에 이 조건들을 추가해야 합니다.
- 확정은 다음 계산과 비교할 기준안 저장이며 과거 집행을 잠그지 않습니다.

## 저장과 백업

데이터는 `%LOCALAPPDATA%\AssignmentScheduler\scheduler.db`에 저장됩니다. 저장할 때마다 버전을 추가하고 직전 상태를 `before_save.db`로 백업합니다. 수동 백업은 현재 입력을 저장한 뒤 전체 DB를 복사합니다. 복원은 백업의 최근 버전을 읽어 새 버전으로 저장합니다. 급여 데이터는 인터넷으로 전송하지 않으며 DB 파일 자체는 암호화되지 않습니다.

## 검증

`python -m unittest discover -s tests -v`

## 실행파일 배포 (추후)

개발 컴퓨터에서 PyInstaller로 Tkinter와 Python을 포함한 배포본을 만들 수 있습니다. 예: `python -m PyInstaller --noconsole --onedir --name AssignmentScheduler app.py`. 이 프로토타입에는 아직 실행파일 배포본을 포함하지 않습니다.
